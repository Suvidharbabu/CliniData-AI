Security & governance

Built for inspectors and auditors

Health data demands tenant isolation, encryption and a trail for every AI decision. These are the controls CliniData AI is designed around.

Security architecture

  • TLS 1.3 at the edge; internal service traffic encrypted.
  • Short-lived JWTs (15 min) with refresh-token rotation; stateless API scaling.
  • RBAC and object-level checks at the service layer, so a user bound to one tenant cannot read another tenant's records even with a guessed ID.
  • MFA mandatory for Admin, CCO and Compliance Officer roles.
  • PHI and sensitive data encrypted at rest (AES-256) with keys in a managed KMS.
  • All LLM calls logged; no customer data sent to external LLM APIs without a data processing agreement.
  • CSRF protection, CORS restricted to registered origins, rate limiting on sensitive write paths.
  • Per-tenant vector namespaces prevent cross-tenant retrieval.

Audit & data governance

  • An append-only audit log records every user action, data access and system event.
  • Every AI decision logs the model, prompt version, response hash and confidence score.
  • Agent execution traces are stored with the full run for accountability and replay.
  • Evidence document hashes are captured at ingestion and verified on every audit package.
  • Tenant data is region-locked; cross-region replication only with explicit consent.
  • Hourly snapshots with point-in-time recovery for Postgres; scheduled graph backups.

In this demo the audit log is protected by a database trigger that blocks UPDATE and DELETE, and row-level security denies all browser-side access to the tables.
